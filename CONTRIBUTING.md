## Contributing to SynOS

Thank you for considering a contribution to SynOS. This project is deliberately built around human-authored, human-understood systems code, and this document exists to keep it that way as the contributor base grows.

### AI-Assisted Contributions
SynOS does not accept "vibe-coded" contributions: code generated by an AI tool or agent and merged by a human who does not fully understand it. Bugs at the kernel level are extremely costly. A subtle memory-safety error in Ring 0, or in an `unsafe` block guarding a hardware boundary, can compromise the security guarantees of the entire system rather than a single process.

The policy is as follows:

- **Code:** All code must be written by a human. AI-generated code is not permitted.
- **Documentation and commit messages:** AI tools may be used to produce a first draft. The contributor must read, verify, and take full responsibility for every word before committing it.
- **Commits:** Every commit must be made by a human. Commits must not carry AI attribution, such as a `Co-Authored-By` trailer naming an AI tool.

Contributors who commit unverified AI-generated content, whether code or documentation, may be banned from the project.

### How to Contribute
At this stage, the project owner is learning kernel development and intends to write the code personally. Code contributions are therefore not being accepted yet. The best way to contribute is to report bugs or suggest improvements by email to lakvijayaku@gmail.com.
